## Deliverable A — `franken_oracle_dump` (Sonnet; CPU run allowed)

`tools/hot-expert/franken/oracle_dump.cpp`, linked against libllama and
ggml from `~/src/llama-glm53/build-hip` (headers `include/`, `ggml/include`).
Loads the model with `n_gpu_layers = 0` (the run happens in the docker image
WITHOUT `--device` flags, so no GPU exists and every op runs on the CPU;
this is allowed), feeds token ids given on the command line as one batch,
and installs `cb_eval` (see `examples/eval-callback/eval-callback.cpp`) that,
for every tensor whose name matches `<name>-<il>` for the names in the list
below, copies the tensor to host (`ggml_backend_tensor_get`) and writes the
LAST token's column as raw little-endian f32 to `<dir>/<name>-<il>.f32`,
plus one line `name il ne0 ne1 ne2 type` in `<dir>/index.txt`. Also dump
`result_norm`, `result_output` (logits) and the model's input embedding
after the PLE add if it is named. Names: all of
`hc_norm hc_gate hc_mixed hc_inject hc_combine attn_pregate attn_gated
attn_output kqv_out indexer_q indexer_k indexer_k_pooled indexer_score
indexer_top_k linear_attn_qkv_mixed z q_conv k_conv v_conv conv_output_silu
alpha beta a_softplus beta_sigmoid state_predelta linear_attn_out
ffn_moe_out ffn_shexp ffn_shexp_gated shared_expert_gate_sigmoid ffn_out

Run it on the ids `[248044, 785, 10945, 315, 1495, 374]` (any 6 ids are fine;

Expect minutes: the CPU forward of a 94 GB model over 6 tokens.

## Deliverable B — `franken_decode` (Opus; build only, no GPU)

`tools/hot-expert/franken/decode/*.hip|.cpp`, one binary, one card (device
0), layers 0–15, one token at a time with a growing sequence. Reuses:
`gguf_model`/`placement` (loader), `ple` (CPU gather),
`tools/hot-expert/m1/m1_native_decode.h` + the kernels of `m1_native.hip`
(routed experts, native IQ3_S/IQ4_NL), `tools/hot-expert/m1/m3_attn.hip`'s
kernels (indexer scan, radix top-k, flash split attention + combine, GDN
delta-rule step), and a Q8_0 GEMV for the trunk that reads ggml's AoS
`block_q8_0` (32 int8 + f16 d — NOT the planar layout of `m5_bench.hip`;
port the kernel shape, change the load). Everything else is new small
kernels (RMSNorm, gated RMSNorm, sigmoid/SiLU/softplus, hc mix, conv1d ring
of 4, L2-norm, IMRoPE with `rope.dimension_sections [11,11,10,0]` on 64
dims, router softmax + top-10 with `expert_weights_scale`, the Q6_K lm_head
is NOT needed in step 2). f32 activations throughout; KV caches for the QSA
layers in q8_0 (K, V) and the pooled indexer keys in bf16 exactly as the M3
harness lays them out; GDN state f32 [48 heads x 128 x 128] and conv state
per layer.

CLI: `franken_decode --model <shard1> --tokens <ids...> --layers 0-15
--oracle <dir>`: uploads layers 0–15 (reuse `upload_placement` for one
device), runs the tokens one by one, and after the LAST token compares every
intermediate it computes with the oracle file of the same name: prints
`oracle <name>-<il> cos=<c> maxabs=<m> ref_l1=<..>` per point and a final
`STEP2 PASS/FAIL` (PASS = every compared point cos ≥ 0.999 and the layer
outputs `l_last`/`hc_combine` of layer 15 cos ≥ 0.999). Also `--time N`:
decode N further tokens (greedy is not needed; feed a fixed id) with
hipEvents around the 16-layer body and print `layers0_15_ms_median`.

Order of work, each with the oracle before the next: (1) embedding + PLE
input → `ple_gated_value`/`hc_init`; (2) layer 0 (GDN) → every named point
of layer 0; (3) layer 3 (QSA) → its points, including `indexer_top_k` as a
set; (4) the loop 0–15 → `hc_combine`-15. The agent cannot run the GPU; it
must therefore keep a CPU reference path (`--cpu`) that runs the same code
on the host in plain C++ for the small kernels so the math can be checked
against the oracle without a GPU (the expert and attention kernels already
have CPU references in their harnesses; reuse them). Report: commit id,
what `--cpu` shows against the oracle for layers 0 and 3, resource usage of
the new kernels, and what is left for the GPU run.
