# Task closeout

The owner had to ask for this after every completed task (2026-10-07, angrily; again 2026-10-12: "why do I have to tell you every time after every done task to do the same shit: end-of-task skill, cleanup governance docs, remove conflicting and stale info etcetera ... INCLUDING pushing to GitHub"). It is part of the task: ALL steps below, unprompted, before the final message, never ask permission for any of them. A task is not done until step 7 passes.

## Steps

1. **Run the check:** `bash ~/Projects/colibri/tools/hot-expert/closeout_check.sh --full` (read-only except a `git fetch`; ~10 s). It checks repo sync (Mac / Gitea / rig, both repos), clean trees, `doc_currency.sh`, that the handoff names the installed serving binary, rig idle/busy, drifted `~/bench` script copies, the installed skill and hook, the memory index, and the GitHub fork's lag (a FAIL while it lags).
2. **Clean up = the whole state of the project is clean, not one tree. Never end a report with 'I am keeping X', 'X is untouched until you decide' or 'WARN: ...' for something you could fix or decide yourself** (the owner, 2026-10-09: "Clean up means CLEAN THE FUCK UP"). The only things that stay are those that genuinely need the owner (say it in ONE line, with what happens on yes and on no; their files are named in the handoff).
   - **Branches:** none left locally on the Mac or the rig in either repo, except the integration branch (`hot-expert-tier`, `main`). A merged branch: `git branch -d`. A branch whose gate passed: merge it (its gate run first, here), then delete it. A finished experiment that must not merge: tag `archive/<name>`, push the tag to Gitea, delete the branch (local, Gitea, rig).
   - **Worktrees and build trees on the rig:** remove them (`git worktree remove --force`) after copying a gated binary to `~/bench/franken_bin/`.
   - **Scratch:** one-off sequencers, gate dumps / reference logits of closed items, temp scripts, `~/bench` copies of removed things, logs of closed chains. A recipe worth keeping goes into `ckpt1006/` first.
   - **Models and downloads:** the served model plus at most the ONE candidate an open owner decision needs.
   - **Background watchers / agents** that are no longer needed (a rig job still running needs a watcher armed and must be reported).
3. **Record the task** (what the scripts cannot write):
   - the plan (`tools/hot-expert/FRANKEN-ENGINE-PLAN-2026-09-15.md`) gets a Rev entry for what changed; CLAUDE.md and the handoff name the new top Rev;
   - the record (`ROME-3x7900XTX-2026-09-04.md`) gets a section at its END with the numbers and which gate passed; a claim found wrong is corrected in an erratum (a section at the end + a short pointer at the claim), never silently edited;
   - the action list: touched rows have the right status (`done` / `dropped` with a Result pointer and a Done-log line), the 'Last updated' line says today and the real next item;
   - the item's plan (DECODE / PREFILL open-items plan): its banner, the item's row and any 'next' / 'prior' sentence now carry the outcome.
4. **Governance audit -- EVERY task, not only when asked.** Launch two read-only Sonnet subagents in parallel (`model: sonnet`), each given the ground truth of today in a short list (top Rev, installed build + sha + rollback, current prefill / decode numbers with how they were measured, the queue, what was dropped / done this task, fork level, branches / worktrees that exist, new rules):
   - auditor A: `CLAUDE.md`, `HANDOFF-2026-10-06b.md`, the memory dir (`MEMORY.md` + every file it lists);
   - auditor B: `ACTION-LIST.md`, the DECODE / PREFILL open-items plans, the plan's top ~10 Revs, the record's last ~6 sections.
   Each lists, with file:line and replacement text: contradictions (with the ground truth or between files), stale 'now / current / next / doing / prior' claims, numbers presented as current that are not, dangling references, history not labelled as history, memory notes that are wrong, duplicated or volatile. **Fix every finding** (or reject it in one line in the report when the auditor is wrong; verify before fixing). Then grep the governance docs for the phrases this task made stale (the old Rev, the old queue, the old fork sha, the item's old status) until only dated history is left. `doc_currency.sh` must PASS.
5. **Land and push everything:** commit (attribution lines from the session's system reminder), colibri: `git push origin hot-expert-tier`, `git push rome hot-expert-tier:refs/heads/p0-sync`, on the rig `git -C ~/src/colibri merge --ff-only p0-sync && git -C ~/src/colibri branch -d p0-sync`; franken-engine: `main` ff on the Mac, push as `claude-bot` with the credential-store helper (never print it), push to the rig over ssh to a side ref and ff-merge there. **Then the public GitHub fork (standing go-ahead from the owner, 2026-10-12):** secret-scan the range first (`R=$(git ls-remote fork refs/heads/hot-expert-tier | cut -f1); git log -p $R..HEAD | grep '^+'` for key prefixes (`ghp_`, `github_pat_`, `sk-`, `xox`, `AKIA`), PEM headers, `password`/`passwd` values, URL credentials, `Authorization:`/`Bearer` values, e-mail addresses, BMC / IPMI details, the Gitea credential file's contents); if clean, `git push fork hot-expert-tier` and note the new level in the handoff (section 1 'Repos' fork line) and ACTION-LIST O1 -- that note is itself a commit, so push Gitea, the rig and the fork once more after it. If the scan finds a real secret: do NOT push, remove it from the commits, report it plainly. franken-engine has no GitHub remote.
6. **Memory:** the state note (`franken-engine-roadmap.md`) says the current state in one paragraph; a new owner correction or confirmed approach is a feedback memory; the index lines match their files; no passwords or secrets.
7. **Re-run `closeout_check.sh --full` until 0 FAIL and 0 WARN** (the fork lag included).
8. **Final report:** short, plain English, few numbers, times in Amsterdam local time. Say what was verified and what was NOT, what genuinely needs the owner (hardware, a quality call), and the one thing to do next. Do not offer to push or to clean up: it is already done.

## Automation

A Stop hook (`closeout_stop_hook.sh`, registered in `~/.claude/settings.json`) runs the quick check when a turn ends and blocks the stop when a repo is unsynced or dirty, the docs fail `doc_currency.sh`, or the GitHub fork lags, while the rig is idle. It never loops, never blocks while a rig job runs, and ignores other projects. If it blocks, this skill -- all of it, the audit included -- is the way out.

Canonical copy of this file: `~/Projects/colibri/tools/hot-expert/skills/task-closeout/SKILL.md`; the installed copy is `~/.claude/skills/task-closeout/SKILL.md` (the check warns when they differ).
