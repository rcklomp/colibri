# M3 microbenchmark: attention at 256k for Qwen3.8-Flash-Next (2026-09-22, design rev 5 §4)

Same discipline as `M1-M5-BRIEF-2026-09-22.md`: build only, the orchestrator
runs it under the rig lock with the cards empty; key=value output.

## What the model computes (GGUF header + `src/models/qwen4exp.cpp` @ 39931761a)

48 layers; every 4th (12 in all) is a full-attention layer with **QSA**
(block-sparse attention): an indexer with 4 heads x 128 dims scores the cached
indexer keys, **mean-pooled per block of `compress_ratio` tokens** (the header
carries no `attention.compress_ratios`; read the default in
`llama-hparams`/`qwen4exp.cpp` and print it as `qsa_ratio=`), selects
**top-k 2048 tokens' worth of whole blocks plus the incomplete tail**, and the
attention proper runs over the selected keys only: 24 query heads x 256 dims,
2 KV heads x 256 (GQA 12:1), IMRoPE, a sigmoid output gate. The other 36
layers are Gated DeltaNet (recurrent, state 128 x 6144 per sequence, no cost
in depth). KV cache in service: q8_0 K and V, 1 088 MiB + 408 MiB (indexer
keys) per card at 262 144 = **~17.9 KB per token over the model** (M0d).

llama.cpp's measured depth cost (§F11-DEPTH): 66 ms a token at 19k -> 165 ms
at 257k, i.e. ~+100 ms for 12 QSA layers at 256k -- ~8 ms per layer. The
bandwidth floor is far lower; M3 measures what plain HIP kernels achieve.

## What to build (`m3_attn.hip`, one card, decode = one query token)

For depth N in {32 768, 131 072, 262 144}, with synthetic but correctly
shaped caches resident in VRAM:
1. `idx_scan_us`: the indexer score for one query against the pooled keys:
   scores[b] = sum over 4 heads of q_h . kpool_h[b] (bf16 keys, f32 accumulate),
   b over N/ratio blocks (if the ratio is 1, over N keys). Report bytes read
   and GB/s next to it.
2. `topk_us`: select the top 2048/ratio blocks from those scores on the GPU
   (a radix-select or a two-pass threshold + compaction is fine; correctness
   over elegance; report which). Output: a list of selected token indices.
3. `attn_us`: gather K and V (q8_0, 2 KV heads x 256) for the selected
   ~2048 tokens, scores for 24 query heads, softmax, weighted V sum, f32 out.
4. `qsa_layer_us` = the three in sequence on one stream, and
   `qsa_token_ms` = 12 x that (print it, it is the design's M3 number),
   with `kv_bytes_per_token` = the K+V+indexer bytes one token adds (from
   the shapes: 2 x 2 x 256 q8_0 + 128 bf16-or-what-the-cache-holds, times
   12 layers) next to M0d's 17.9 KB measurement.
5. Also `gdn_step_us`: one Gated DeltaNet decode step for one layer with the
   real sizes (state 128 x 6144 per head group as `llama-graph.cpp`'s
   `build_rs`/recurrent path lays it out; a plain kernel), and x36 as
   `gdn_token_ms` -- the constant per-token attention cost that does not
   depend on depth.

Numerics: each kernel against an fp32 CPU reference on the same synthetic
data (max abs, cosine; `CHECK_FAIL` exit 1 below 0.999 cosine, and a zero
output is a FAIL, never a pass). Medians over 1 000 iterations after 100
warm-ups, hipEvent timing. Build in the same docker image, same worktree
(`~/src/colibri-m1`, branch `m5-harness`, `tools/hot-expert/m1/`), Makefile
target `m3_attn`, run script `run_m3.sh` (root in the container, as
`run_m1.sh` after its fix). The agent runs nothing on the GPUs.
